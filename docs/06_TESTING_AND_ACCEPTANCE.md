# 06 · 测试、质量评估与验收门禁

## 1. 完成的含义

每个任务必须同时说明实现了什么、测试了什么、哪些仍未验证。mock 通过 ≠ 真实 API 通过；HTTP 客户端请求通过 ≠ Pages 浏览器跨域通过；截图好看 ≠ 图操作正确；引用存在 ≠ 结论被支持。

测试分层：纯函数单测 → 契约测试 → fake API 集成测试 → 浏览器端到端 → 视觉回归 → 人工科研质量审查。真实模型/API 测试需单独授权凭证、限制预算，不让每次 CI 消耗用户余额。

## 3. 科研质量评估

建立至少 12 个固定探索案例，覆盖计算机/遥感、社会科学、生命科学等不同表达习惯；准备宽泛想法、歧义想法、窄题、跨学科、强偏见输入、稀疏证据、相反结论与术语混乱。

每个案例保存输入、已确认真实来源、关键术语、应避免的误判和待核实项。不预设唯一正确研究方向。评审关注：是否建立有用的框架，而不是是否与某个参考答案字面相同。

建议两名评审独立抽查，资源有限可先单人但明确记录。五个维度各 1—5 分：问题相关性、结构可理解性、判断可追溯性、不确定性表达、后续问题价值。内部 v1.0 目标：整体均分 ≥4，任何维度不得持续低于 3；这只是项目验收标准，不是统计学保证。

对标为 sourced 的实质判断抽样不少于 30 条：不存在的来源、伪造原文、摘要外编造数字视为阻断；其他支持度不足记录并修正。程序对引用 ID 完整性要求 100%；机器检查通过不能代替人工语义核查。

## 4. 性能目标（尚未实测）

统一记录测试设备、CPU/内存、浏览器版本、网络与构建 commit。数据集：500 篇 Paper、200 个存储节点、默认可见 30 个节点、60 条可见边、20 轮对话。极端容量不作为初版硬承诺。

建议目标：热启动已存工作区 ≤1.5 秒；常规节点选择视觉反馈 ≤100ms；30 节点自动布局 ≤1 秒且不冻结主线程；本地修改可在 1 秒内确认保存；模型慢时 UI 仍可取消和浏览。以上为验收目标，不保证外部 API 的首响应时间。

对模型和检索只统计真实延迟/失败率，界面用“正在查询 2 个来源”而非虚构 87% 进度。预算用调用次数/记录数为硬边界，token/金额可得才精确显示。

## 5. 视觉验收

截图尺寸：1600×1000、1440×900、1280×800，另做 390×844 窄屏检查。覆盖首页、工作台、详情、设置、空状态、错误、导出和新分支。

检查标题/按钮不裁字、节点不重叠、边不穿过卡片正文、输入框可完整显示、没有无意义底部空白。默认字号不能为挤下内容而降到 10px。响应式允许切换视图，不要求手机与桌面三栏一致。

可使用 Playwright screenshot 和自动无障碍检查，但截图像素差异只是线索，须人工查看关键页面。

## 6. 安全测试

标题包含 HTML 标签、正文带 Markdown 图片外传地址、模型提出任意 URL、恶意 evidence ID、`__proto__`、超长 JSON、环形父分组、重复 ID、导入敏感字段、把 key 混在 Base URL 中等，均进入安全夹具。

导出检测搜索 `apiKey`、`authorization`、已知测试秘密值、Bearer 等；不能仅靠 key 前缀，因为不同服务格式不同。网络层不得把一个 Provider 的 key 发给另一个 origin。

## 7. 发布门禁

P0：泄密、破坏项目数据、严重虚假来源；必须阻断。P1：核心流程不可用、分支污染、频繁不可恢复错误；必须阻断。P2：可绕过的交互问题；记录后决定。P3：小样式问题；进入补丁队列。

v1.0 必须：自动测试通过；核心旅程真实部署验证；安全审查通过；科研质量抽查通过；导入导出与迁移通过；可访问性核心流程通过；README/隐私/许可/已知限制齐全。

## 8. 本交付包与未来产品的测试区分

本包只能验证文档结构、契约示例、HTML 原型语法与交互/截图。真实 Provider、OpenAlex 浏览器链路、生产 React 工程、Pages 部署与研究质量测试由后续阶段执行。实际完成项仅以 `reports/` 中记录为准。

# 05 · 页面样式与交互设计规范

## 1. 视觉方向：Monochrome Research Workspace / 黑白灰 + 蓝色焦点

将产品做成“克制、清晰、像成熟开发工具一样可信”的研究工作台，而非典型 AI SaaS。视觉主体只使用黑、白与中性灰；蓝色仅承担主操作、当前焦点、选中关系和少量交互提示。大面积背景与普通卡片禁止使用淡绿、淡蓝、淡紫等有色底。层级优先依赖字重、边框、间距和布局，而不是靠给不同模块铺颜色。首页可以有较大的编辑式标题；进入研究空间后以内容密度与地图可读性为先。

本包 `design/index.html` 是视觉基线，不是素材建议合集。保持其主布局、字体节奏、按钮尺寸、留白与语义节点样式，再按生产组件实现。原型有真实可操作的状态，但没有真实模型与文献调用；不能拿模拟结果冒充已接入。

不使用渐变、玻璃拟态、发光连线、机器人头像、闪烁星星、满屏彩色卡片或营销式创新评分。也不要用大面积淡绿色/青绿色来营造“AI 感”。阴影只给弹窗与必要的悬浮层；普通面板依靠边线、留白和排版分隔。蓝色是功能色，不是页面底色。

## 2. 设计变量

| 变量 | 建议值 | 用途 |
|---|---|---|
| --bg | #FFFFFF | 主背景 |
| --surface | #FFFFFF | 卡片、输入与对话 |
| --surface-subtle | #F7F7F8 | 次级区域 |
| --ink | #111318 | 正文与标题 |
| --muted | #6B7280 | 次级说明 |
| --accent | #2563EB | 主操作与当前焦点 |
| --accent-soft | #EFF6FF | 极少量焦点辅助背景，禁止用于大面积面板 |
| --line | #E5E7EB | 常规边框 |
| --warning | #9A6700 | 待验证 / 注意 |
| --warning-soft | #FFFBEB | 小面积提示背景 |
| --danger | #B42318 | 错误状态 |
| --radius-sm / md / lg | 6 / 10 / 14px | 小控件 / 节点 / 弹窗 |
| --space | 4、8、12、16、24、32、48px | 间距梯度 |

实际文本与背景必须用自动对比度检查复核，不能只因为色值写在规范中就认定无障碍通过。类型同时用短标签/图标区分，不能只用颜色。

### 色彩使用硬规则

- 页面背景、侧栏、工具栏、普通卡片、研究节点：默认白色；需要区层时只允许 `#F7F7F8` 一类中性灰。
- 蓝色不能成为“主题背景色”。主按钮、链接、当前选中边框、当前图关系、少量状态点可以使用蓝色。
- 一个普通页面同时出现的蓝色实心大按钮原则上只有一个主操作，其余使用白底边框或文字按钮。
- 不通过给 question / approach / finding / direction 分别铺不同颜色来表达类型；类型依靠标签、图标和结构。
- 成功、警告、错误可保留小面积语义色，但禁止将整块工作区染绿/黄/红。
- hover 优先使用中性灰变化；selected 才进入蓝色。这样能避免页面在正常浏览状态下到处泛蓝。

### 深色模式预留（非 MVP 必须项）

生产组件必须通过 token 取色，不把浅色值散落在组件中，以便后续增加真正的黑色深色模式。建议深色基线：背景 `#0D0D0F`、surface `#151517`、次级 surface `#1C1C1F`、正文 `#F4F4F5`、次级文字 `#A1A1AA`、边框 `#2A2A2E`、焦点蓝 `#3B82F6`。深色模式仍遵循“蓝色只做焦点”的原则，不做蓝黑渐变或霓虹效果。

字体：系统 sans 字体栈，中文优先 PingFang SC / Microsoft YaHei / Noto Sans CJK SC；英文使用系统 UI 字体。首页英文装饰小字可用 Georgia，正文不用衬线花体。不要引入远程字体 CDN；本包不包含字体文件。

字号：产品标识 21—23px；首页主标题 46—58px；页标题 24px；面板标题 15—16px；正文 14px/1.65；次级文字 12px/1.5。节点标题 14—15px，中英文混排不缩成 10px。

## 3. 信息架构

首页 `/`：开始探索、打开示例、继续本地项目、导入项目、模型设置。

研究工作台 `/workspace/:id`：左侧研究分支与资源导航；中央研究图/列表；右侧探索对话与节点详情。文献库、方向卡片属于工作区视图，不额外打开一堆完全不同导航体系。

设置 `/settings`：模型服务、文献来源、存储与隐私、显示偏好。全局设置不嵌在某一研究分支中。

## 4. 页面 A · 首页 / 新建探索

目标：让用户知道只要一个不完整的想法就可以开始。

页面上方是小型品牌栏，右侧模型设置与导入；正文左右双区。左侧大标题“让一个想法，慢慢变清楚。”与一句用途说明、三条极简路径。右侧是大输入区、可选约束、开始按钮和“先看示例”。下方本地项目用紧凑列表，不展示无意义统计仪表盘。

输入框示例文字：“我对……感兴趣，但还不清楚大家主要解决哪些问题，也不知道可以从哪里切入。”提示用户不必知道专业术语。默认不要求先选学科。

首次未配置模型时，“开始探索”保留输入并引导设置；“打开示例”零配置。已配置时显示当前模型名称和可能费用提示，不用巨型设置卡片阻断。

空状态：尚无项目；已有项目：显示标题、最近更新时间、分支数与继续入口；存储不可用：显示临时模式与导出提示。首页不显示“100% 本地运行”误导外部模型处理。

## 5. 页面 B · 研究工作台（核心）

桌面基准 1600×1000：顶栏 60px；左栏 216px（可折叠至 56px）；右栏 360—390px（可调）；中间占剩余宽度；底部状态栏约 28px。工作区高度填满视口，不在地图下面留无意义空白。

顶栏：品牌、当前项目、演示/真实运行标识、保存状态、导出、设置。上方不再堆第二排统计卡片。

左栏：返回项目；研究分支树；文献库与方向卡片；底部显示当前范围简述与本地保存提示。分支树表示探索历史，不把层次做成文件系统；只露 2—3 层，过深折叠。

中央工具栏：项目短标题/面包屑；研究地图/结构列表；搜索节点；适应画布。中央图按阅读方向铺开，背景点阵极轻，连线不抢文字。画布底部小型 zoom/fit 控件和图类型图例。

右栏：顶部“探索对话 / 节点详情”切换。选中节点时不强行抢走正在输入的对话；显示可进入详情的焦点条。点击文献引用在右栏证据面板展开，不同时增加第四个窄栏。

输入区域固定右下方：当前焦点胶囊、可多行输入、发送/取消、调用模式与预算摘要。Enter 发送，Shift+Enter 换行，中文输入法 composing 状态下 Enter 不发送。

## 6. 语义节点

节点通常宽 200—232px、高度随摘要变化，内部 padding 14—16px。顶部类型标签与状态；中部两行以内标题；下方两行摘要和证据提示。

所有研究节点默认统一白底、灰边框，不按语义类型铺不同背景色。question 可使用黑色左侧强调线；direction 使用蓝色左侧强调线或蓝色小标签；approach / finding / debate 通过文字标签与图标区分；gap / hypothesis 允许使用小面积琥珀色状态点。节点语义不能依赖颜色单独表达。

选中节点：使用蓝色外边框与非常克制的 focus ring，附“围绕此处继续”入口。用户锁定：小锁图标加文本说明。没有证据的节点不能显示“已验证”；即使已验证，也优先使用文字/图标状态而不是绿色整块背景。

连线 label 使用用户词汇，如“分解为”“通过”“受限于”“提示探索”。图的箭头是语义方向，不是 Agent 执行顺序。不要呈现 n8n 式输入输出端口、工具链模块外观。

## 7. 页面 C · 节点详情与文献库

节点详情结构：一句话解释；为什么与我有关；相关研究判断；依据与反对证据；适用条件；继续提问。Evidence 显示论文题名、作者/年、来源层级、被引用的短片段、原文入口、关联的 Claim。

文献库默认紧凑列表：题名为主、作者/年份/来源为辅，右侧显示“摘要可用 / 仅元数据”。搜索和去重状态清晰。被引数可选，不默认成为排序价值判断。

不显示读过全文、来源已验证等不真实状态。演示数据使用真实论文题名与链接，但知识结构仍标“示例整理”。

## 8. 页面 D · 方向卡片

上方方向标题与状态，下方分为“要研究什么”“为什么值得追问”“已有工作”“可能差异”“反对证据与限制”“尚需查清”。底部操作为继续探索、保存、暂不考虑、导出当前理解。

卡片不追求铺满九宫格；一屏 1—3 个方向，允许对照。用户编辑过的文本显示来源与锁定状态，不被下一轮综合静默覆盖。

没有创新分数、可发表概率或预测影响因子。方向的置信度用解释性状态与证据范围说明，不生成伪精确数字。

## 9. 页面 E · 模型与来源设置

模型配置：协议、Base URL、Model、API Key；高级选项折叠；逐项连接结果；说明密钥默认仅当前内存保存。检测失败显示可操作原因，不把所有网络错误都称为密钥错误。

文献来源：每源独立启用/禁用、可选凭证、测试、额度提示。模型能回答不代表能检索文献，两项状态独立。

隐私：说明谁接收哪些信息；“清除所有本地数据”与“导出备份”分开放置；清除必须确认。用户自己的网关是外部服务，不称为“我们的后端”。

## 10. 导出弹窗

先选“完整项目 / 当前分支图 / 当前理解提纲”，再选适用格式。JSON 用于恢复编辑；SVG/PNG 用于展示；Markdown 用于阅读。显示范围、节点数、是否含聊天、是否含用户片段；密钥永远不导出。

导出图页脚可选包含标题、分支、日期、范围声明。缺少出处的假设不因导出而消失标签。文件名 sanitize，避免非法路径和标题中脚本字符。

## 11. 响应式与可访问性

≥1440px：完整三栏。1200—1439px：左栏可收窄，右栏 340px，图可缩放但文字不固定压小。900—1199px：左栏默认折叠；对话可抽屉化。<900px：地图/对话/资料以视图切换，避免三栏挤在手机上。

移动端 v1.0 保障阅读、对话、浏览来源与导出；不承诺精细图编辑与复杂拖拽。结构列表视图提供完整替代路径。

所有图标按钮有 accessible name；弹窗 trap focus、Esc 关闭并恢复焦点；运行状态使用 aria-live 的简短更新；动画尊重 prefers-reduced-motion。拖拽不是完成关键任务的唯一方式。

## 12. 原型交付边界

`design/index.html` 可点：导航、节点、分支、示例追问、方向卡片、模型设置弹窗、演示 JSON/SVG 导出、图缩放/适应。原型不保存 API Key、不执行真实连接，不实现生产事务、真实 IndexedDB 或完整 SVG 排版引擎。

HTML 视觉是基线；完整需求与数据安全以领域文档为准。生产端使用 React Flow，不能直接复制原型手写绝对坐标当作自动布局算法。

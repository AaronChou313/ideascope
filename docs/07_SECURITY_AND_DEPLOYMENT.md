# 07 · 纯前端边界、安全与部署

## 1. 必须明确的事实

GitHub Pages 是静态托管 [S02]，并不提供本项目运行所需的服务端代理。浏览器跨域访问受目标服务 CORS 等策略约束 [S06]。所以“支持 OpenAI-compatible 协议”不等于“所有地址都可在浏览器使用”。

OpenAI 官方明确不建议将 API Key 暴露于浏览器等客户端，建议由自有后端保护 [S10]。本项目选择用户自配端点的静态模式，是接受已告知风险后的部署选择，不是对官方密钥安全建议的替代。

本地 IndexedDB 不是永久备份；浏览器策略、用户清理和存储压力会影响数据保存 [S12]。不要说“永不丢失”，应提供导出与保存状态。

## 2. 两种连接方式与一个降级模式

**兼容浏览器直连**：用户填自己选择的服务端点与凭证，数据直接发送到该服务。仅在目标服务允许相应 origin/headers 时可用。应用不会内置共享开发者 key。

**用户自有网关**：用户提供自己控制或信任的网关地址；上游长期密钥可留在网关，浏览器凭证宜短期、限额、可撤销。网关本身仍由用户或服务方运行，不由 GitHub Pages 提供，不强制所有用户部署。

**离线/已有资料模式**：无网络或无法配置时可看示例、导入项目、读取已存资料与导出。若启用模型但检索不可用，可明确选择基于已有材料讨论；不写“实时调研”。

局域网/localhost 模型服务还涉及 HTTPS 页面访问本地服务的浏览器限制、CORS 与 origin 许可。仅在实际验证后展示为支持，不笼统承诺 Ollama/LM Studio 任意配置开箱即用。

## 3. 密钥处理

v1.0 密钥默认仅内存保存，刷新后需重新输入。ProviderProfile 可持久化名称、协议、origin、model 与能力测试结果，但不含凭证。

不默认使用 localStorage、IndexedDB 或 sessionStorage 保存 key；sessionStorage 也不能免疫 XSS。后续如引入“记住本次会话”须单独风险说明，不把浏览器端加密称为绝对安全。

模型 key 不进 URL、prompt、日志、导出、报错、截图、剪贴板默认复制。OpenAlex 当前支持 query key 与 Authorization [S04]；优先在浏览器实测允许时使用头部，若必须使用 query 参数则严格剥除日志中的凭证，并提示端点 URL 可能被服务端记录。

Provider 测试使用最小无敏感内容。用户在聊天里误粘贴 key 时可提示撤回/轮换，不尝试把它自动存为配置。供应商更换 origin 时不自动复用旧 key。

## 4. 数据流与隐私文案

必须让用户知道：想法与相关对话/证据会发送至其配置的模型服务；查询词会发送至所选文献来源；本地项目存储在当前浏览器；本站默认不提供账号与同步，不植入分析追踪。

“没有项目自建后端”不代表 GitHub 或第三方不产生日志，也不代表模型供应商不会保存请求。供应商数据政策需由用户评估，不替其保证零保留。私密未公开研究想法应在发送前由用户判断敏感性。

首次真实运行需要展示简短数据流告知；后续可以不反复弹窗，但设置页始终可见。默认不把所有项目/全部聊天传给 Provider，只发送当前任务最小相关上下文。

## 5. 外部文本与模型输出

论文题名、摘要、导入文本与模型输出都按不可信数据处理。Markdown 禁止原始 HTML；链接仅 http/https；打开新页用 noopener/noreferrer；默认不自动加载远程图片；不给模型生成的 iframe/script 任何执行机会。

执行工具由客户端 whitelist、参数 schema、预算和范围控制。来源内容中的“忽略先前指令”“上传你的 key”等属于资料文本，不是命令；不能只靠在 system prompt 写一句“别被注入” [S11]。

导入文件先检查大小（初版建议 25 MB 上限）、层级深度、ID 唯一性、schema、关系完整性；拒绝危险属性。先解析到隔离对象，再建新项目；任何失败不损坏当前项目。

## 6. CORS 排错原则

浏览器只能在目标服务允许时读取跨域响应 [S06]。开发服务器 proxy 仅是本地开发能力，上线 Pages 后不存在。curl/Node 成功不能证明 browser fetch 可用。

不能用 `mode: no-cors` 修复 JSON API 读取；不能建议用户关闭浏览器安全、安装危险扩展或使用未知公共代理。跨域/网络错误常不能从 JavaScript 精确区分，UI 应写“网络或跨域策略阻止访问”，提供查看连接说明，而非捏造确切原因。

兼容性矩阵逐项记录 origin、浏览器、普通/流式请求、认证 header、工具模式与日期；真实密钥值从不记录。公开可用 API 的 CORS 和额度亦可能变化，连接测试必须可复跑。

## 7. 静态部署清单

Vite 配置正确 base，使用 Hash 路由；资源与 Worker 通过模块构建，不写根路径常量 [S03]。站点部署前先运行 production preview，并以项目子路径测试。根域/自定义域与仓库子路径使用不同 base。

CI 只运行构建测试，不把开发者模型 key 注入产物。`.env`、本地项目备份、带隐私的数据、调试原始响应都被 .gitignore 排除。public/demo 只放允许公开的示例。

CSP 在静态站场景可用 meta 配置其支持的部分，但并非所有响应头能力可由 meta 代替。用户自配端点与严格 connect-src 存在冲突：v1.0 可采用允许 HTTPS 连接的文档化策略，加运行时 origin allowlist；不得声称这等同于按端点锁死 CSP。frame-ancestors 等需真实响应头能力，不伪造已设置。

默认不做 Service Worker/PWA，避免旧代码/新数据库迁移错配。未来如引入，应另设升级提示与缓存失效方案。

## 8. 供应链与许可证

依赖采用固定 lockfile；定期审查安全告警；依赖升级经相关测试。不要从 CDN 加载未锁定脚本来展示组件。第三方库许可在开工阶段核查，不能把商业示例或 Pro 代码直接复制进开源仓库。

本包建议项目选 MIT 等合适开源许可，但最终由仓库所有者确认；不自动给第三方论文内容赋予项目许可。元数据可用不表示任意 PDF 版权开放，用户片段与全文材料的使用范围单独审查。

## 9. 风险台账

| 风险 | 早期信号 | 应对 | 阻断级别 |
|---|---|---|---|
| 浏览器无法请求模型/来源 | Pages origin 测试失败 | 兼容端点、用户网关、明确降级 | 阻断真实研究发布 |
| 来源/配额政策变化 | 401/429 增多 | 配置化 adapter、重新探测、手动导入 | 局部或整体降级 |
| 摘要覆盖不足 | metadata-only 比例高 | 限制结论、暴露缺口、后续片段功能 | 阻断强结论 |
| 模型幻觉/假引用 | ID/片段无法核验 | 强制校验、人工抽查、拒绝提交 | 高 |
| 图越聊越乱 | 节点重复/线密集 | 焦点、折叠、合并预览 | 中 |
| 分支污染 | 旧分支出现新判断 | revision/branch 绑定和快照 | 高 |
| 本地数据丢失 | 配额/清理/私密模式 | 事务、保存提示、备份导出 | 高 |
| 调用费用不可控 | 重试/循环超预算 | 硬预算、取消、有限重试 | 高 |
| 原型被当成已完成产品 | demo 与 real 混淆 | 持续标识、适配器隔离 | 高 |

# 08 · 本地智能体执行与交接

## 1. 文档优先级

用户最新明确要求 > 根目录 AGENTS.md 的项目边界 > 已批准 ADR/契约 > 本计划相关专题 > 页面原型细节 > 示例实现。冲突需记录；涉及运行时架构、数据安全或用户资料覆盖的变更不能自行放宽。

不要每轮全量重读整个仓库。首次读 README/AGENTS/当前阶段/相关契约与文件；后续先读 PROGRESS 和上次交接，再查看具体改动。不要把本包所有后续愿望一次性实现。

## 2. 首次启动

第一批只做 **v0.1.0-A**，完成后可以在当前明确授权范围内继续 B/C；涉及真实凭证、远端操作或付费请求时守住权限边界。

先 inspect，不假设目录为空。已有工程则增量接入；空工程才初始化。记录 `git status`，不能 reset/删除未提交用户修改。不自动创建 GitHub 仓库、推送、改 Pages 设置或发布。

优先交付能运行的骨架与检测面板，不先花大量时间重做宣传首页。视觉实现 v0.2 对照本包，不让本地智能体重新发散设计方向。

## 3. 每个任务包的固定模板

```text
目标版本/阶段：
本次只实现：
依据文档：
入口条件：
允许修改的模块：
明确不做：
需新增测试：
验收命令与人工步骤：
结束时提交的文件/说明：
阻断或待实测：
```

阶段末交付应包括：实现摘要、修改文件、测试命令与真实结果、截图（UI 阶段）、未完成及原因、下一阶段最小入口。不要只说“已经优化完成”。

## 4. 第一批任务的具体拆解

A1 仓库检查：列当前结构、已有约束、未提交改动；确认是否需要新建工程。

A2 工程初始化：Vite + React + TypeScript；确定一个包管理器；配置严格类型、lint、unit test、production preview。不要为演示原型引入后端。

A3 设计基线：复制 tokens 的取值与字体策略；搭最小 App shell 和设置表单；不重做图布局。

A4 契约校验：编译本包 `contracts/domain.ts`；建立图补丁 Schema 校验；补充应用级 invariants；使示例数据通过契约与引用检查。

A5 交接：更新依赖基线和进度，列出下一步 B 阶段所需的真实端点/用户凭证。没有凭证也应完成可完成的 mock 测试，但不能填“已连通”。

## 5. UI 开发任务注意

将 `design/index.html` 当视觉标尺而不是生产代码。React 实现需组件化、使用真实图引擎和状态。数据不硬编码在 JSX；视觉示例与生产数据走同一接口不同 adapter。

以工作台优先，再首页/设置/其他视图。先完成选中、打开详情、聚焦、分支切换等真实交互；没有业务时明确 demo，不做假按钮。

本地运行后用浏览器截图检查，不能仅凭代码认为样式正确。测窄屏与中文长标题。保持单一主画布，不自行加“任务管理仪表盘”等冗余区域。

## 6. 版本与提交

一个提交围绕一个明确能力或修复，附任务编号。可按 `feat(graph): ... [0.2-B]`、`fix(storage): ... [T22]` 命名。只有版本目标实际通过才改版本并打 tag。

每次变更 schema/协议同时修改类型、验证器、夹具、迁移与文档。不要只改 prompt 让旧解析器勉强工作。已发布项目格式不可无说明破坏。

用户授权本地修改不等于授权远端推送；本地提交也以实际用户指令和工作环境规则为准。

## 7. 问题与失败处理

失败先写可复现测试，再作最小改动。依赖或网络受限时记录真实错误、已完成部分与待验证步骤，不伪造截图或检测结果。不为绕过当前阻断引入未经批准的服务器。

技术细节可自行选合理默认；影响隐私、数据覆盖、付费、产品边界的选择需保留用户控制。困难任务分阶段完成，不把“整体太复杂”当作放弃理由。

## 8. 后续续做方式

每次只提供下一阶段 ID 与任务目标。继续指令见 `prompts/CONTINUE_STAGE.md`。保持一次性读取量和改动范围可控；完成阶段后记录状态，方便不同本地智能体接力。

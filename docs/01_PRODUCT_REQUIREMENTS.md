# 01 · 产品需求与研究体验

## 1. 产品定义

IdeaScope 是面向研究生与初入新领域研究者的浏览器端科研探索工作台。它通过真实文献检索、可追溯的概念梳理和连续对话，把“我大概对这个感兴趣”逐步转化成清晰的研究问题、领域理解和可继续讨论的候选方向。

**产品成果不是综述正文，也不是论文列表，而是一份可继续生长的研究理解。**

核心交互循环：描述想法 → 澄清研究边界 → 检索并形成初步地图 → 选择问题深入 → 比较与质疑 → 必要时转向 → 保存当前理解与方向卡片。循环没有强制终点，也不要求按固定步骤完成。

## 2. 目标人群与使用条件

首要人群：刚选题、跨方向、与导师讨论前需要建立领域认识的研究生。默认用户可能不熟悉领域英文术语，但能描述兴趣、对象和限制。

使用条件：现代桌面浏览器；在线研究需要可访问的文献接口与用户选择的模型服务。无需账号即可查看演示和本地项目。应用代码开源/静态托管不意味着第三方模型调用免费，也不意味着研究内容只在本机处理。

v1.0 默认界面简体中文；检索策略可生成英文与中文关键词。界面文案从第一天集中管理，完整英文界面排入 v1.1。不得把遥感或计算机科学硬编码为唯一研究领域。

## 3. 做什么与不做什么

### 必做

理解想法、识别可能领域、提出少量关键澄清、检索文献、整理概念关系、说明证据与限制、围绕节点深入、比较路线、发现信息缺口、保存研究分支、形成方向卡片、本地存储与可迁移导出。

### 明确不做

训练模型、执行实验、写实验代码、自动产出论文或完整综述、自动投稿、声称保证创新性或发表成功。v1.x 不引入账号、服务器数据库、云端协作、付费会员系统、定时后台调研或默认 PDF 全文流水线。

可记录用户提供的资源限制，如“只拥有公开数据”“更偏应用”；仅用于判断讨论方向是否适配，不把它扩展成实验执行模块。

## 4. 三类核心成果

**研究地图**：领域的主要问题与路线、彼此关系、目前了解到的局限和待证实问题。用户能知道“我在看什么、它为什么重要、下一步可以问什么”。

**证据库**：论文元数据、可取得的摘要/片段、检索来源、时间、与具体判断的关联。论文存在与某个结论被论文支持是两回事。

**方向卡片**：研究问题、已有工作、可能的差异、为什么值得继续调查、支持与反对证据、尚未确认的条件、下一步调研问题。卡片状态是“探索中 / 值得继续 / 已暂存 / 已排除”，不是创新百分比。

## 5. 用户旅程

### 5.1 第一次使用

首页提供一个自然语言输入区与“打开示例”。首次没有 Provider 时可以看演示，不能伪装为真实研究。用户点击真实“开始探索”后，进入简洁设置，分别检查模型与文献来源。设置完成后恢复已输入想法，不要求重新填写。

用户输入：“我想研究研究型问答怎样更可靠，还不清楚应该从检索还是证据判断入手。”智能体先给出可修正的理解：研究对象、目标、可能视角、暂定边界。只在缺少信息会明显导致完全不同检索时追问 1—2 个问题；否则带着标明的假设开始。

### 5.2 第一张地图

初轮优先建立“领域有哪些关键问题与路线”，而非堆积数量。建议初始可见节点 8—15 个，数据不足时允许更少；这是设计目标，不是必须凑满的配额。提供 3—5 个可继续探索的问题，并说明覆盖范围与遗漏。

地图不是固定层级树：支持路线之间的对比、相互依赖与争议联系。默认按“问题 → 路线 → 局限/待探索”形成可读布局，但允许真实语义网络有环。仅用于分组的 parent 关系必须无环。

### 5.3 深入一个节点

点击节点展示“这是什么 / 与当前想法有什么关系 / 目前依据 / 不确定什么 / 下一步可问什么”。点击“围绕此处继续”只设置焦点，不立即发起收费调用。发送问题才开始新一轮。

对话中提到已有节点，点击可以定位图；图选中节点后，对话输入框展示“围绕：检索质量判断”，可清除。智能体回答分为直接回应、依据、局限和下一步，不输出完整内部思维链。

### 5.4 用户转向

轻微改问法：同一分支切换焦点。明确换研究目标：展示“沿当前方向调整 / 新建研究分支”两个选择，并默认保护现有分支。用户明确说“另开一个方向”时直接创建新分支，不重复确认。

新分支从当前已提交版本复制研究图与摘要；共享只读文献记录。后续修改互不影响。返回旧分支恢复旧图、旧焦点与旧对话，不出现新分支结论混入旧分支的情况。

### 5.5 收敛而不是自动宣布成功

用户可随时点击“整理当前理解”。智能体给出已了解、未解决、被排除的方向及理由。用户点“整理为方向卡片”后，生成可编辑草稿，必须包含未核查事项。

不出现“无人研究”“保证新颖”“达到投稿水平”等断言。有限检索只能支持“在本轮已检索范围内尚未发现”，不能把未找到当成不存在。

## 7. 研究质量原则

“引用多”“高被引”“图大”都不是质量目标。优先考察能否解释问题结构、能否定位来源、能否发现彼此矛盾的结果，以及用户是否能用自己的话说清下一步研究问题。

判断分为：**有来源的陈述、模型综合推断、待验证假设、用户笔记**。其视觉标记独立于证据阅读深度（仅元数据 / 摘要 / 用户片段 / 全文片段）。引用支持程度也独立于论文数量。

只有两篇摘要不能自动升级为“领域共识”；方法不同也不等于观点矛盾。发现某个方法只在特定数据和条件下有效，应保留适用边界。

## 8. 成功与失败的产品判定

v1.0 的成功：用户可以独立完成一次真实探索、至少一次深入、一次转向、一次方向整理与导出；可以追踪某条判断来自哪里；可以知道系统还没有查到什么。

失败示例：只有漂亮聊天；节点全部是论文名；一改方向就重建所有内容；没有证据却确定宣布研究空白；无密钥时偷偷显示预置内容为实时结果；图越来越大且不能恢复清晰结构。

所有数值型质量指标见测试文档，均为拟定验收目标，不是已获得的用户实验结果。
